# Domain Docs

This is a single-context repository. Read the root `CONTEXT.md` before exploring or changing the weekly-report workflow. Read relevant decisions in `docs/adr/` if that directory exists. A missing ADR directory needs no setup task; record decisions there when they are actually made.

Use the domain vocabulary in `CONTEXT.md` for ticket titles, acceptance criteria, tests, and reports. If a new concept needs a stable name, record it in the glossary before using competing synonyms. Surface any conflict with an existing ADR explicitly.
